Issues found during polish
--------------------------
1. Riposte ordering: 0.11.0 inserted the NCMM riposte before the vanilla martial-arts dodge-counter block, allowing the modded counter to pre-empt/stack awkwardly with vanilla counter semantics.
2. Riposte eligibility: the NCMM counter lacked the vanilla one-third-stamina gate and an explicit dead-attacker guard.
3. Self-damage: general outgoing/execute multipliers used avatar-source alone and could therefore amplify avatar self-damage.
4. Kill farming: revived monsters explicitly receive zero kill XP in CDDA, but the 0.11.0 NCMM kill bridge still fired move/stamina/Momentum rewards.
5. Event integration readability: patched monster.cpp emitted a raw numeric Host event ID instead of a named Host-owned integration function.
6. Crafting UI mismatch: the real crafting success roll received the technical bonus, while recipe_success_chance() still displayed the vanilla estimate.
7. Lockpick floor: a global five-second clamp allowed ordinary lockpicks to bypass vanilla's 30-second minimum after Quick Entry reduction.
8. RU terminology: descriptions translated CDDA action points/moves as whole "turns", overstating +5/+10/+15 move rewards.
9. Partial-apply recovery: the reactive idempotency probe checked patched gameplay files but not the new Host kill-wrapper declaration/definition.
10. Source probes were broader than the exact code paths now modified.

Corrections applied
-------------------
- Vanilla martial-arts dodge counter is preserved first; NCMM riposte is a fallback and cannot double-counter the same dodge.
- Riposte requires >= 1/3 max stamina and a living adjacent attacker; recursion guard and move-refund logic remain.
- Outgoing/execute path now requires source != target.
- Kill rewards/NCMM kill event require avatar attribution and kill_xp > 0.
- Added Host-owned runtime_player_kill_notify() wrapper and header declaration.
- Idempotency probes now require both wrapper declaration and implementation before treating the patch as complete.
- recipe_success_chance() receives the same capped crafting.success_roll_flat adjustment as the real roll.
- Quick Entry uses a 30-second floor for ordinary lockpicks and a 5-second floor for perfect lockpicks.
- Russian move terminology and kill-trigger wording are corrected.
- reactive_technical_hooks.source.v2 adds exact upstream anchors for the newly hardened paths.
