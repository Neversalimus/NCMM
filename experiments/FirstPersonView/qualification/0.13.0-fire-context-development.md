# Native firing context: development evidence

This is a completed firing sub-suite, **not installer qualification or a frame-time result**.
The subsequent walking fixture failed after resetting its previous camera position;
the follow-up restores a rendered baseline before that test. Both actual keyboard
backends and the remaining scenario breadth still require the updated binary.

## Cause and change

Native `target_ui::run` temporarily owns the input and screen. Treating that
context as leaving gameplay suspended perspective drawing, allowing the native
map to be presented. The fix keeps the user's persistent FP preference separate
from a bounded targeting scope. Its monotonic token restores the scope once;
explicit F6-off and native menus retain their existing behavior. It neither
forces FP on nor changes native confirmation, ammunition, moves or ballistics.

The legacy control runs the old context policy in the same instrumented binary;
it is not a historical executable. Its fifth presented image visibly contains
the native map. Fixed cases use ordinary SDL input, `game::handle_action`, the
native aim activity and actual window presentation.

## Limits and follow-up

The option strings alternated in 6e9, but its native cached keyboard mode was not
updated: the input journal observed character mode throughout. The new fixture
applies `options_manager::update_options_cache`, records the resolved mode and
counts actual DEFAULTMODE results; option strings alone cannot pass that gate.
Pointer-only LMB, a successful vertical shot, dead targets, changed items,
vehicle fire and native fault cases remain additional required coverage.
The controlled firing series does not advance ordinary enemy AI and is not
manual play. Lossless readback and GPU debug instrumentation invalidate timing
claims from this run.
