# Frame upload ordering: complete diagnostic controls

These controls preserve unfavorable results and are separate from final installer and performance acceptance. They do not measure isolated GPU execution time.

R18 is a private, matched MSVC 19.38.33145 Release module experiment: static arms, dynamic-flag arms, static arms. The flag forces repeated arm geometry uploads; it is diagnostic only and is absent from the shipping source. Its worse first-frame timings also prevent treating it as a release optimization.

R19 uses the exact same shipping source3e9 PSX module in old, split-copy, old Hosts. All 30 non-Host payload files are identical. Required frame copies are submitted separately before recording consumers, with static arm meshes still cached. Each short run has 12 scene/viewport/renderer records, 12 steps and 48 cold plus 48 warm turns. Both groups use ordinary unattached native execution without GPU debug.

Do not promote source5ae into PR218. Same-module unattached controls are mixed, and the complete ten-scene comparison retains material ordinary-rotation regressions despite correct queued GPU behavior. Short phase improvements do not establish lower complete-frame latency. The private dynamic-mesh flag remains diagnostic only. No Full run was dispatched for the rejected source.

The split-copy street and multi-level short controls improve whole rotation frames, but city record time alone is misleading: the split run shifts about 4.377ms into Present and does not consistently improve the complete city frame. Acceptance must use complete first/rotation timings from all ten scenes, rather than upload/record phase reductions. Medians of independently aggregated stages are not additive. A 12-step p99 is not reliable rare-tail evidence.

## Queued GPU correctness

Both actual RTX 4090 / D3D12 runs pass: MSVC and Clang ASan/UBSan; 16 queued distinct pose snapshots, four queued lighting snapshots and 32 queued teardown cycles per run. The unchanged warm fixture uploads 272 bytes. The standalone tests use SDL 3.4.0; packaged native Hosts use static SDL 3.4.10. These checks establish queued-data and lifecycle correctness, not a native speedup.

Integration run [39118919964](https://github.com/Neversalimus/NCMM/actions/runs/39118919964) completed with both module jobs and both pinned native Host jobs successful. Its final required gate correctly rejects the selected Integration tier because this source change requires Full. Actual logs state: Required full; selected integration. This expected tier rejection is not a native test failure and must not be presented as an overall green Full run. Both candidate archives were verified against all 32 payload files and 44 native source inputs.

The production change adds one ordered GPU command submission for existing required copies. It adds no CPU fence/wait, device, swapchain, shader, public ABI or simulation change. Copy submission and acquiring the draw command buffer remain inside full callback/record/upload timing; public submit_ms remains the final draw submit only. Static mesh, material and texture data remain cached. Existing lifecycle draining handles failed submission/acquisition.
