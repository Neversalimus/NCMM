- Host module state showed AWS init_failed.

ROOT CAUSE
CDDA options_manager::load() runs before ncmm::initialize(). Global options.json may already contain
NCMM_AWS_* entries serialized from the NCMM Experimental page. Vanilla options_manager::deserialize uses
options[name].setValue(value); for an unknown name, which creates a default VOID cOpt. When AWS later
registers the real bool/int/float/enum setting, the World Settings API sees an existing option with the wrong
page/type and returns false. AWS geography registration therefore fails and module init returns false.

A second persistence defect was found adjacent to the init failure: WORLD::load_options() in exact 0546
only restores page == world_default. NCMM experimental settings are present in WORLD_OPTIONS but their
saved values were ignored on world reload because their page is ncmm_experimental.

FIX
1. options.cpp generated patch now owns ncmm_deferred_option_values.
2. options_manager::deserialize defers only unknown names with prefix NCMM_; normal CDDA unknown-option
   behavior is left unchanged.
3. All four typed registration paths (bool/int/float/enum) apply a deferred value after the real typed cOpt
   has been created or refreshed; 4/4 creation paths and 4/4 refresh paths are covered.
4. worldfactory.cpp generated patch restores both world_default and ncmm_experimental entries.
5. worldfactory.cpp is now part of World Settings v2 required-file, marker and patched-source audits.
6. Host build cache identity changed to .ncmm_host_0831_persistence_build.sha256 /
   v8.2-host-0831-persistence so the current 0.8.3 Host binary cannot be reused for this source change.
7. Runtime verification report schema advanced to 3 and now includes module_failures plus state/lifecycle/reason.
   NCMM.cmd selftest prints each failed test detail instead of only the test ID.
